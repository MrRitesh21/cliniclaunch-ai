## Factual metrics and activation

- Records use `created_at >= trial_started_at AND created_at < min(server_now,trial_ends_at)`. Clinical invoice totals exclude void invoices. Collections come from **actual `patient_payments.amount` with `paid_at` in the window**, joined to the same-tenant non-void invoice; an older invoice's payment collected during trial is correctly counted. Invoice totals are not payment collections or SaaS revenue.
- Existing `patient_visits` has no completion status/time. `completed_visits` is explicitly **null / Not tracked**, not guessed from a visit record. Recorded visits and completed appointments are separate factual counters. Completion tracking remains a genuine product/schema limitation for the parent to decide, not a fabricated metric.
- Days active counts distinct UTC dates with real persisted setup/clinical activity. This is not logins, estimated hours saved or elapsed trial days. Existing records contribute their stored activity date; new mutation triggers retain one actual activity marker per UTC day. The `clinicx_activation_days` ledger is server-owned with RLS and no authenticated DML.
- Database triggers capture first patient/appointment/visit/prescription/invoice/payment, doctor/staff addition, actual clinic creation/profile completion and actual onboarding start/completion flags. Unique `activation:<kind>` subscription events prevent repeated first-action events; timestamp is database `now()`, not a browser tracking call. Existing foundation provides trial-start/signup provisioning authority. Login analytics are not invented: no auth-login hook was audited as a trustworthy activity source.
- Checkpoint producer captures a trial-created-record window ending at the exact backend day-N timestamp, even on a late pre-expiry execution. Current stored status/totals are used; **this is not historical state reconstruction**. Both effective and recorded timestamps and snapshot semantics are exposed/documented. Old persisted checkpoint payloads are not rewritten. A legacy all-time checkpoint exposes null checkpoint usage instead of failing the new DTO parser or relabeling it as trial activity.
- Current all-time inventory/seat/doctor/feature usage remains the existing recommendation input. Growth stays the default for unactivated small clinics; meaningful solo usage can recommend Starter/Growth, and multi-doctor requires Professional/Enterprise as dictated by the existing catalog. Recommendations never select a plan or force checkout.

## Lifecycle and durable notification behavior

`runTrialEngagementJobs` invokes existing `expire_lapsed_subscriptions()` with **no caller clock**, which in turn invokes existing `clinicx_run_trial_jobs()`. Trial boundaries remain immutable start +720 hours and grace +168 hours. Day 0 uses the existing atomic trial-start outbox; days 7/15/21/25/28 use existing repeat-safe event keys; day 30 audits trial-expired/grace; day 37 suspends. No retention/deletion job is added. Database access restrictions work even when the scheduler is late; grace reads/export and post-grace authorized billing/account/export/support are preserved.

- Existing outbox remains one row per event. `prepared_at` separates transactional inbox/materialization from external completion. Latest eligible checkpoint wins for marketing; stale queued trial reminders after paid activation/expiry are suppressed. Day-30 `grace_period` is not a second notification of the same expiry boundary. Missing owners do not silently consume messages.
- Inbox rows and durable email intents materialize in one transaction. Email intents require current owner membership, verified auth email and explicit owner consent. Claim rechecks eligibility/consent, and suppresses removed recipients, changed email addresses or obsolete events. Recipient and copy are frozen in each delivery row so retry idempotency payloads do not drift after a deployment/account change.
- Email delivery is service-only and uses `FOR UPDATE SKIP LOCKED`, per-claim random token, 15-minute lease, stable delivery-ID-based provider key, exponential retry up to 1 hour, bounded batches and sanitized errors. Missing `RESEND_API_KEY` leaves email unclaimed and does not label it sent. Provider HTTP plus response-body JSON consumption use a 15-second AbortSignal deadline. A stale/lost lease cannot acknowledge another worker's delivery.
- A worker crash after send can retry with the same provider idempotency key. Resend documents 24-hour key retention ([official docs](https://resend.com/docs/dashboard/emails/idempotency-keys), verified via official search result; direct extractor was network-blocked). Uncertain delivery older than **23 hours** or 20 attempts requires operator review and is not automatically resent. Review rows leave the outbox incomplete; exactly-once live delivery is **not** promised. Never reset the key/first-attempt timestamp without independent provider reconciliation. SQL monitoring: count pending / `needs_review` in `clinicx_notification_delivery`, and inspect unprepared or undelivered `subscription_outbox` rows using authorized service tooling without logging recipient data.
- Payment-event inbox copies reuse existing payment outbox kinds; existing billing reminder migration remains intact. This scheduler does **not** replace the separately owned financial reconciliation worker: parent may compose `runBillingReconciliation` separately using its existing provider adapter and ownership contract.
