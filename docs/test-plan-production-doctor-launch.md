## 3. High-Priority Test Cases

### TC-01: Concurrent Public Slot Booking Collision
- **Scenario:** 2 parallel HTTP requests book the exact same doctor and slot timestamp (`2026-11-06T18:00:00+05:30`).
- **Expected:** Exactly 1 request receives `201 Created` with appointment ID. The second request receives RFC 9457 `409 Conflict` with `code: APPOINTMENT_SLOT_COLLISION` and immediate alternative open slot suggestions. Zero double-booking records in database.

### TC-02: Asynchronous Outbox Resilience
- **Scenario:** Meta WhatsApp API returns 500 or timeout during appointment confirmation.
- **Expected:** Booking completes with `201 Created` in <500ms. Notification job in `notification_outbox` marks `status: retry`, increments `retry_count`, and retries with exponential backoff (capped at 3). On terminal failure, alerts reception dashboard.

### TC-03: Prescription PDF PHI Confidentiality
- **Scenario:** Direct unauthenticated access to storage URL vs tokenized signed route.
- **Expected:** Direct storage URL returns 403 Forbidden. Only authorized tokenized route `/c/:slug/rx/:token` with valid HMAC and unexpired timestamp serves the PDF.

### TC-04: Razorpay Webhook Signature & Idempotency
- **Scenario:** Send valid Razorpay webhook event, followed immediately by identical replay.
- **Expected:** First call updates subscription status to `active` and records payment invoice. Second identical call is recognized as duplicate via event ID and returns 200 OK without creating duplicate invoice or triggering side effects.

### TC-05: 7-Day Billing Grace Period (2 AM Friday Scenario)
- **Scenario:** Subscription payment fails on scheduled renewal.
- **Expected:** Clinic enters `grace_period` for 7 days. Doctor consultation and prescription generation continue working with a banner notice. Past clinical records remain 100% accessible.
